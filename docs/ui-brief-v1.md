# Event Scout UI v1 on Cloudflare: build brief

Owner of design decisions: main lane (Champ). The frontend lane executes this file exactly.
Branch to cut from: `cf/native` (pushed to origin). Work branch: `cf/ui-v1`. PR target: `cf/native`. Never touch `master`.

## 0. Goal in one line

Replace the field-sales surfaces of the 7,000-line vanilla `mobile-frontend.html` with a React app built from the
21st.dev components below, served by the same Cloudflare Worker, against the API that already runs at
`https://event-scout.deep-ae0.workers.dev/api`. Admin screens stay on the legacy page for this version.

## 2. Deliverable format

- New Vite + React 19 + Tailwind 4 + shadcn app in `web/` (repo root). `npm run build` emits static files.
- `worker/scripts/build-assets.sh` builds `web/` and copies `web/dist/*` into `worker/public/`, so `/` serves the new app,
  and copies `mobile-frontend.html` to `worker/public/admin.html`.
- No new hosting, no Pages project, no other domain. The Worker already falls through to assets for non-`/api` paths.
- Node: `source ~/.nvm/nvm.sh && nvm use 24`. 21st.dev installs through the shadcn CLI with `TWENTY_FIRST_API_KEY` from the frontend profile env.

## 5. Screen-by-screen spec

1. **Auth.** `POST /api/login/` or `/api/register/` with JSON. Success returns `user_id, name, email, is_admin, session_token`.
   Store the whole object in `localStorage['eventScoutUser']` (same key the legacy page uses, so admins move between both
   pages signed in). Every later call sends `X-API-Key: <session_token>`. Any 401 clears storage and returns to Auth with
   "Your session has expired. Please log in again." Logout: `POST /api/logout/` then clear.
2. **Scan (default tab).** Pick or shoot one or many photos. Each goes through the queue (port `scan-queue.ts`), one at a time:
   `POST /api/add_contact_from_image/?user_id=<id>` multipart field `file`, 30 s client timeout. Responses:
   `status: "success"` (show extracted name and company, contact saved), `status: "duplicate"` (show "Already saved: <existing_name>",
   no retry), HTTP 400 (no card text found: Retry or Enter manually), network or 5xx (keep the photo, Retry).
   Measured on this backend: p50 3.6 s, p95 6.4 s per card. A Manual entry form posts `POST /api/add_contact/` with
   `{user_id, contact: {name, email, phone, linkedin, company_name, title, notes}}`; use "N/A" for blank email, phone, linkedin.
3. **Contacts.** `GET /api/list_contacts/?user_id=<id>&date_filter=<today|yesterday|last_week|last_month>` (omit for all).
   Search filters client-side. Header shows the count. Export button downloads `GET /api/export_contacts/?user_id=<id>&format=csv`
   via fetch with the header, then a Blob link (a plain href cannot send the header).
4. **Contact detail.** `GET /api/contact/<id>?user_id=<id>`, edit with `PUT /api/contact/<id>?user_id=<id>` (JSON of changed fields),
   delete with `DELETE /api/contact/<id>?user_id=<id>` after a confirm. vCard is built client-side (port `downloadVCard` from
   `mobile-frontend.html`, search for `BEGIN:VCARD`).
5. **Ask.** `POST /api/converse/` with `{user_id, query, conversation_history: [{role, content}...], top_k: 4}`. Render `response`
   as text and `retrieved_contacts` as list rows that open the detail sheet. Never send `admin_mode`.
6. **Me.** Profile and Event tabs: `GET` and `PUT /api/user/profile/?user_id=<id>`; Event tab edits `current_event_name` and
   `current_event_description` (new scans are tagged with that event). My card tab: `GET`/`PUT /api/user/card/`, Share button
   `POST /api/user/card/generate_token/` shows `shareable_url` and the QR. Admins see a link "Admin console" to `/admin.html`.

## 6. Data honesty

No sample contacts, scores or counts in the shipped build. Empty states say what to do ("Scan your first card").
Loopback-only fixtures are allowed for tests, never reachable on the deployed host.

## 7. Acceptance criteria (each is a command or a measured check)

1. `cd web && npm run build && npm test` pass on Node 24; report gzipped JS size from the build output.
2. `cd worker && npm run typecheck && sh scripts/build-assets.sh` pass; `worker/public/index.html` is the new app and `worker/public/admin.html` is the legacy page.
3. Local QA: `cd worker && npx wrangler dev --port 8791` serves the new app against the real remote D1 is NOT allowed. Use
   `npx wrangler dev --port 8791 --local` with `npx wrangler d1 migrations apply event-scout-db --local` first, so tests write to a
   local database only. Register a throwaway user locally.
4. Playwright (real Chromium) drives: register, sign out, sign in, manual add, scan one card image from
   `~/repos/event-scout/bench/cards/c01_photo.jpg` (local OCR calls Workers AI through wrangler's remote AI binding; if it is not
   reachable locally, record that and mock only that one response, labelled), list shows the contact, edit notes, export CSV
   downloads a file whose first bytes are `EF BB BF`, Ask returns a reply, generate card link shows a QR, delete, logout.
5. `responsive-viewport-qa` at 360, 390, 768 and 1280: no horizontal overflow (`scrollWidth == innerWidth`), every control >= 44px,
   text contrast >= 4.5:1 measured. Screenshots in `web/qa/screenshots/`.
6. `visual-verify` gate run and its report path included.
7. `grep -rn $'\u2014\|\u2013' web/src` returns nothing (no em or en dashes in copy or code).
8. Do not deploy. The main lane deploys after review.
